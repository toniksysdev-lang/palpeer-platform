# Deploy Palpeer API on Render

Blueprint file: [`render.yaml`](../render.yaml) (API + admin + Postgres + Redis).

## 1. Create the Blueprint

1. Open [Render Dashboard](https://dashboard.render.com/) → **New** → **Blueprint**.
2. Connect GitHub and select **`toniksysdev-lang/palpeer-platform`**.
3. Confirm `render.yaml` is detected → **Apply**.
4. When prompted for `sync: false` variables, fill at least:

| Variable | Example / notes |
|----------|-----------------|
| `CORS_ALLOWED_ORIGINS` | `https://admin.yourdomain.com,http://localhost:5173` |
| `PALPEER_SENDPULSE_CLIENT_ID` | SendPulse **API** Client ID (Settings → API → Client credentials). Not the SMTP email login. |
| `PALPEER_SENDPULSE_CLIENT_SECRET` | SendPulse **API** Client Secret. Not the SMTP password. |
| `PALPEER_SMTP_USERNAME` / `PASSWORD` | Optional SMTP fallback; also used as SendPulse OAuth login when `SENDPULSE_CLIENT_*` are empty (must be API ID/Secret for REST to work) |
| `PALPEER_MAIL_FROM` | `noreply@yourdomain.com` |
| `PALPEER_MAIL_FROM_NAME` | `PALPEER` |
| `PALPEER_MAIL_HEADER_FROM` | same as from (optional) |
| `PALPEER_FCM_ENABLED` | `true` for real push |
| `PALPEER_FCM_CREDENTIALS_JSON` | Firebase service-account JSON (single line) |
| `ADMIN_BOOTSTRAP_EMAIL` | First admin user email (optional) |
| `GOOGLE_CLIENT_IDS` | Comma-separated OAuth client IDs, or leave empty |
| `APAYLO_ENABLED` / `APAYLO_API_KEY` / `APAYLO_SHARED_KEY` | CAD Interac rail — required for Pool Funds (Apaylo) and CAD funding |
| `APAYLO_SANDBOX` | `true` for sandbox keys |
| `KORAPAY_ENABLED` / `KORAPAY_SECRET_KEY` / `KORAPAY_PUBLIC_KEY` | NGN rail — required for Pool Funds (Korapay) and NGN funding |
| `KORAPAY_SANDBOX` | `true` for `sk_test_` / `pk_test_` keys |
| `KUDA_*` | Live NGN funding (dynamic collection) + withdrawals; set `KUDA_ENABLED=true`, `KUDA_SANDBOX=false`, `KUDA_CLIENT_ACCOUNT_NUMBER`, webhook user/pass, and disable offline/auto/demo settle flags |

`PALPEER_MAIL_PROVIDER` defaults to `auto` (SendPulse REST when client ID/secret are set). Raw SMTP (`PALPEER_SMTP_*`) is optional fallback — outbound SMTP is often blocked on Render free.

**Inbox / spam:** the From domain must pass SendPulse SPF+DKIM (and align with DMARC). See [`mail-deliverability.md`](mail-deliverability.md).

`JWT_SECRET` is generated by Render. Postgres/Redis are wired automatically.

## 2. Plans (free tier)

- **Web (`palpeer-api`)**: `free` — spins down after ~15 minutes idle; cold start can take ~1 minute. Java Docker may OOM on free (512 MB); upgrade to `starter` if builds/runs fail.
- **Static (`palpeer-admin`)**: free CDN static site; SPA routes rewrite to `index.html`.
- **Postgres (`palpeer-db`)**: `free` — 1 GB storage; **expires 30 days** after creation unless upgraded.
- **Redis (`palpeer-redis`)**: `free` — small RAM, no persistence across restarts, private network only.

## 3. After deploy

- Health: `https://<service>.onrender.com/actuator/health`
- API base: `https://<service>.onrender.com/api/v1`
- WebSocket: `https://<service>.onrender.com/ws` (SockJS) / `wss://…/ws/websocket`

The Blueprint also publishes **palpeer-admin** (static). Its build reads `PALPEER_API_ORIGIN` from the API service and writes `VITE_API_BASE_URL` (`…/api/v1`) and `VITE_WS_URL` (`…/ws`).

After the first deploy, set `CORS_ALLOWED_ORIGINS` on **palpeer-api** to the admin origin Render assigns (for example `https://palpeer-admin.onrender.com`). The API will not accept the admin’s browser calls until that value is saved and the API redeploys.

Mobile (`EXPO_PUBLIC_API_BASE_URL`) still needs that same HTTPS API URL when you build an APK.

## 4. Custom domain (optional)

In the web service → **Settings** → **Custom Domains** → add `api.yourdomain.com` and follow DNS instructions.

## 5. Local Docker still works

`docker-compose.yml` overrides profile/host for local Postgres/Redis. Dockerfile default is `prod`; compose sets `SPRING_PROFILES_ACTIVE=dev`.
